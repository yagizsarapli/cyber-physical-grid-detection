## A. Foundational FDIA / state-estimation attacks

1. Liu, Ning, Reiter — [False data injection attacks against state estimation in electric power grids](https://dl.acm.org/doi/10.1145/1952982.1952995) (ACM TISSEC, 2011). The foundational FDIA paper — shows an attacker with network topology knowledge can construct an attack vector that lies in the measurement Jacobian's column space and is invisible to residual-based bad data detection. Every "stealth" attack in this project's own code (the model-consistent FDIA) is a direct descendant of this construction.
2. [False Data Injection Attacks against State Estimation in Smart Grid](https://escholarship.mcgill.ca/downloads/j6731869v) (McGill).
3. [Detecting False Data Injection Attacks on DC State Estimation](https://www.researchgate.net/publication/228373879).
4. [False data injection attacks targeting DC model-based state estimation](https://ieeexplore.ieee.org/abstract/document/8273918/) (IEEE).
5. ★ [Targeted False Data Injection Attack against DC State Estimation without Line Parameters](https://arxiv.org/pdf/2102.11896) (arXiv:2102.11896). Confirmed from the abstract: relaxes the classic Liu-Ning-Reiter requirement of full topology/line-parameter knowledge — attacker succeeds with less information than this project's own attack model assumes. Evaluated on IEEE 14-bus against residual, ML, and topology-based detectors. A harder (less-informed-attacker) threat model worth citing as future stress-test direction, same category as entry 15.
6. ★ [Smart False Data Injection attacks against State Estimation in Power Grid](https://arxiv.org/pdf/1809.07039) (arXiv:1809.07039). Confirmed: "smart" = requires system-configuration knowledge (same full-topology assumption as this project's own attack model); validated on a microcontroller-based bad-data-detection implementation rather than a named IEEE bus system. Thin but real confirmation, no numbers to cite.
7. ★ [A Survey of Machine Learning Methods for Detecting False Data Injection Attacks in Power Systems](https://arxiv.org/pdf/2008.06926) (arXiv:2008.06926). Confirmed from the abstract: taxonomy is essentially binary — residual-based BDD vs. ML/data-driven methods; no specific future-work gaps stated in the abstract itself (would need the full text for that). Still the best available entry point for a related-work section's opening paragraph, just don't over-claim what its abstract promises.

## B. Stealthy / model-consistent AC FDIA (the attack family this project builds on)

8. ★ [Detecting False Data Injection Attacks in AC State Estimation](https://ieeexplore.ieee.org/document/7035067/) (IEEE). Directly relevant: this project's `apply_model_consistent_attack` constructs `a = h(x_attack) - h(x_true)` for the exact reason this line of work identifies — AC-consistent attacks evade the same chi-square residual test this project also uses as its `residual_only` baseline.
9. [Modeling and performance evaluation of stealthy FDIA in presence of corrupted measurements](https://arxiv.org/pdf/1605.06180) (arXiv:1605.06180).
10. ★★ [Controllable Blind AC FDIA via Physics-Informed Extrapolative AVAE](https://pmc.ncbi.nlm.nih.gov/articles/PMC11820443/) (PMC). Confirmed and substantial: "blind" means the attacker needs **none** of admittance matrix, topology, state-estimation Jacobian, or historical measurements — strictly weaker knowledge than this project's own attacker (who is assumed to know the model exactly, as in Liu-Ning-Reiter). Tested on IEEE-14 (106 measurements) and IEEE-118 (978 measurements) using **real 2023 NYISO load data** (not purely synthetic, unlike this project). Reports 90-100% detection-evasion success against chi-squared and normalized-residual tests depending on configuration. This is the strongest concrete argument in the whole bibliography that this project's own threat model is the *easier* end of the spectrum — a harder, blind-attacker stress condition is a natural, well-evidenced next step beyond entry 15/5's low-magnitude and no-line-parameter variants.
11. ★ [Learning Without Adversarial Training: A Physics-Informed Neural Network for Secure Power System State Estimation under False Data Injection Attacks](https://arxiv.org/pdf/2604.22784) (arXiv:2604.22784, 2026). Confirmed: PINN constrained by power-flow consistency, with a learned dynamic weighting between data loss and physics loss (55% MAE reduction over fixed-weight PINN variants); tested on **IEEE 118-bus** against baseline-distortion and "stricter residual-profile-matching" FDIA (a close analogue of this project's own stealth construction) — but, like this project, trained only on clean data with **no adversarial retraining**. A genuine parallel worth citing directly in this paper's §6/§8 discussion of untested robustness against adversarially-optimized (not just stealthy-by-construction) attacks.
12. [False data injection attack against smart power grid based on incomplete network information](https://www.sciencedirect.com/science/article/abs/pii/S0378779624001822).
13. [Physical model learning based false data injection attack on power system state estimation](https://www.sciencedirect.com/science/article/abs/pii/S2352467724002534).
14. [False data injection against state estimation in power systems with multiple cooperative attackers](https://www.sciencedirect.com/science/article/abs/pii/S0019057820300537).
15. [Physically Consistent Null Space Alignment for Detection of Low-Magnitude False Data Injection Attacks](https://arxiv.org/pdf/2606.08473) (arXiv:2606.08473, 2026) — directly relevant to this project's HARD/HARDER stress test (attacks pushed toward the noise floor); worth reading closely if this becomes a real submission, since it may already address the exact "low-magnitude attack" regime this project's §2 stress test explores empirically.

## C. Deep-learning FDIA detection

16. ★ [Dynamic Detection of False Data Injection Attack in Smart Grid using Deep Learning](https://arxiv.org/pdf/1808.01094) (arXiv:1808.01094). Confirmed: CNN+LSTM time-series anomaly detector on **IEEE 39-bus** — one data point toward this project's own §7 question of whether a bigger, standard system changes the picture (different method and question, but same scale class). No specific accuracy figures in the abstract.
17. [Detection of Stealthy False Data Injection Attacks Against State Estimation in Electric Power Grids Using Deep Learning Techniques](https://dc.uwm.edu/etd/2504/) (UWM thesis).
18. ★ [False data injection attack in smart grid: Attack model and reinforcement learning-based detection method](https://www.frontiersin.org/journals/energy-research/articles/10.3389/fenrg.2022.1104989/full) (Frontiers). Confirmed: FDIA detection framed as a Markov Decision Process solved with an optimized Deep Q-Network, swept across **IEEE 9/14/30/57-bus** systems, 96.95-100% detection depending on attack type and state-estimation filter (EKF/UKF) used. One of the few sources found that actually sweeps multiple network sizes for the same method — useful methodological example for the swept-scale follow-up this paper's §7/§9 calls for.
19. [Detecting Stealthy False Data Injection Attacks in Power Grids Using Deep Learning](https://ieeexplore.ieee.org/document/8450487/) (IEEE).
20. ★ [Towards Adversarial-Resilient Deep Neural Networks for False Data Injection Attack Detection in Power Grids](https://arxiv.org/pdf/2102.09057) (arXiv:2102.09057). Confirmed: defends a DNN FDIA detector against adversarial examples using random input padding at train and inference time; abstract claims this "significantly reduces adversarial-attack effectiveness" with "negligible impact" on normal detection performance, but gives no specific numbers. Same robustness-caveat category as entry 23 (LESSON) — neither of this project's own trained detectors have been tested against adversarially-crafted (as opposed to naive/stealth-but-not-adversarial) inputs.
21. ★★ [False data injection attack detection in dynamic power grid: A recurrent neural network-based method](https://www.frontiersin.org/journals/energy-research/articles/10.3389/fenrg.2022.1005660/full) (Frontiers). **A genuine complication for this paper's own §7 finding, worth citing directly against it.** Confirmed: LSTM + 2 fully-connected layers, evaluated across **five** systems — IEEE 9/14/30/118/300-bus. For continuous attacks, accuracy is *stable* across all five scales (0.937-0.945, a ~1-point spread from 9-bus to 300-bus); the much bigger accuracy gap (94% vs. 76%) is between attack *type* (continuous vs. discontinuous), not network size. This is the opposite pattern from this paper's own §7 result, where the topology-fusion advantage specifically (not detection accuracy generally) degraded going from 5-bus to 14-bus. The honest synthesis for §8: general FDIA-detection accuracy may be fairly scale-stable (as this paper shows across 9-300 buses); it may specifically be the *topology-relational feature's marginal advantage* that is scale-sensitive, which is a narrower and more precise claim than "detection gets harder at scale."
22. ★ [Detecting False Data Injection Attacks in Smart Grids with Modeling Errors: A Deep Transfer Learning Based Approach](https://arxiv.org/pdf/2104.06307) (arXiv:2104.06307). Confirmed: addresses a different generalization axis than this project's §6 — not unseen attack *types*, but unknown/dynamic *line parameters* (sim-to-real transfer, source domain = simulated data, target = real data with unknown parameters), tested on IEEE 14-bus and 118-bus. No specific accuracy numbers in the abstract. Relevant as a second, distinct kind of "generalization gap" a real deployment would face beyond the one this project already tested.
23. ★ [LESSON: Multi-Label Adversarial False Data Injection Attack for Deep Learning Locational Detection](https://arxiv.org/pdf/2401.16001) (arXiv:2401.16001). **Corrected after reading**: this is not a detection+localization method paper to benchmark against — it's the opposite framing, an adversarial-attack paper showing multi-label deep-learning FDIA *locational detectors* can be fooled by adversarially crafted attack vectors that evade detection and localization simultaneously. Relevant as a robustness caveat for this project's own trained detectors (untested against adversarial, as opposed to naive/stealth, attacks), not as a same-scope comparison point.
24. [Detection of false data injection attacks leading to line congestions using Neural networks](https://www.sciencedirect.com/science/article/abs/pii/S2210670722001883).

## D. Graph / topology-aware methods (most directly comparable to this project's core claim)

25. ★ [Topology-Aware Graph Neural Network-based State Estimation for PMU-Unobservable Power Systems](https://arxiv.org/abs/2506.03493) (arXiv:2506.03493, 2026). The closest published match to this project's central question — uses graph convolution + attention specifically to exploit topology for state estimation under partial observability. This project's finding (topology-fusion helps on a small radial-ish network, not clearly on a bigger meshed one) is a natural complication to raise against this paper's framing.
26. ★ [PowerGNN: A Topology-Aware Graph Neural Network for Electricity Grids](https://arxiv.org/pdf/2503.22721) (arXiv:2503.22721, 2025). Confirmed: a state-*forecasting* task (not attack detection), tested on the **NREL 118-bus** system, RMSE 0.13-0.17, beats FC-NN/linear-regression/rolling-mean baselines. Different task than this paper's, but another 118-bus data point for the "does topology-awareness hold at bigger/different scale" question this paper's §7 raises — worth noting in Discussion that even topology-positive GNN papers cluster around a handful of standard scales (14/39/118-bus) rather than sweeping scale as a variable.
27. ★ [Robust and Interpretable Graph Neural Networks for Power Systems State Estimation](https://arxiv.org/pdf/2603.23357) (arXiv:2603.23357, 2026). Confirmed: uses an interpretable Graph Neural Additive Network (GNAN), tested on multiple **SimBench grids with topology changes and varying measurement penetration** — notably, the abstract itself admits "GNAN trails GAT in accuracy" (i.e. the interpretable variant is *not* the best-performing one), a useful honest-tradeoff citation for this paper's own accuracy-vs-something-else discussions. No baseline comparison against non-GNN methods in the abstract.
28. [Physics-informed graphical neural network for power system state estimation](https://www.sciencedirect.com/science/article/abs/pii/S0306261923019669) (ScienceDirect).

## E. Attack/event localization

29. [Localizing Load-Altering Attacks Against Power Grids Using Deep Capsule Nets](https://arxiv.org/pdf/2209.02809) (arXiv:2209.02809). **Corrected after reading**: evaluates on IEEE 14-, 39-, and 57-bus systems (multi-scale — worth studying for how *they* handled the scale question this project's §5 only tried once). The attack is botnet-driven demand manipulation of high-wattage smart appliances (a physical load attack), not FDIA on state-estimator measurements — a materially different threat model from this project's, so it's a weaker comparison point than first assumed. The 94.11% figure attached to this entry in an earlier pass could not be re-confirmed from the abstract on a second, closer read — dropped rather than repeated unverified. Worth reading the full PDF (fetch failed twice here) before citing any number from it.
30. ★ [Localization of Coordinated Cyber-Physical Attacks in Power Grids Using Moving Target Defense and Deep Learning](https://arxiv.org/pdf/2207.12339) (arXiv:2207.12339). Confirmed: actively perturbs line reactance via D-FACTS devices to invalidate an attacker's prior knowledge (moving target defense), then localizes line outages with CNN + meta-learning (MAML) for fast retraining after topology reconfiguration; "IEEE test systems," unspecified which, no numeric accuracy in the abstract. Notable as an *active* defense (changes the network to expose the attack) rather than this paper's fully passive detection — a real alternative paradigm worth naming in Discussion.
31. ★ [An Online Approach to Cyberattack Detection and Localization in Smart Grid](https://arxiv.org/pdf/2102.11401) (arXiv:2102.11401). Confirmed: regularized linear regression on state-estimation residual sparsity patterns, tested on unspecified linear and nonlinear system models; claims to beat conventional methods on both detection delay and localization accuracy, no numbers in the abstract. The "detection delay" framing is close in spirit to this paper's own §5 latency work, though not with an explicit real-time budget.
32. [Intrusion Detection, Measurement Correction, and Attack Localization of PMU Networks](https://napier-repository.worktribe.com/output/3735060/) (Napier).
33. ★ [Real-Time Detection of Hybrid and Stealthy Cyber-Attacks in Smart Grid](https://arxiv.org/pdf/1803.00128) (arXiv:1803.00128). Confirmed: online detection with simultaneous estimation of unknown, time-varying attack parameters; despite the title, the abstract gives no actual latency/timing numbers, no named test system, no accuracy figures — "real-time" here is a design goal stated in the title, not a measured claim in the abstract. A useful contrast for this paper's §5, which does measure and report actual millisecond figures against a stated budget rather than asserting real-time-ness qualitatively.
34. ★ [Local Cyber-physical Attack with Leveraging Detection in Smart Grid](https://arxiv.org/pdf/1708.03201) (arXiv:1708.03201). Confirmed: not a detection paper at all — an *attack* paper (IEEE SmartGridComm 2017) showing how to mask a real line outage at one location while falsely implicating another, to continuously deceive the control center's topology estimate. No test system or numbers in the abstract. Relevant as a reminder that this paper's own threat model (measurement spoofing) is one of several distinct attack surfaces in this literature — topology/outage deception is a different one, not covered here.

## F. State estimation / bad-data-detection fundamentals

35. ★ [Computational Methods in Power System State Estimation: A Recent Critical Review, Current Challenges and Future Research Directions](https://link.springer.com/article/10.1007/s11831-025-10327-3) (Springer, *Archives of Computational Methods in Engineering*, 2025). Good candidate for the "background" citation on WLS/chi-square/LNR test methodology this project's own `21_..._HARD.py` implements.
36. ★ [Machine Learning Assisted Bad Data Detection for High-throughput Substation Communication](https://arxiv.org/pdf/2302.05949) (arXiv:2302.05949) — "ResiGate". Confirmed: uses ML as a pre-filter to cheaply discard non-suspicious measurements before expensive full bad-data detection runs on frequent substation traffic; claims "zero error while sustaining high throughput," no concrete latency/throughput numbers in the abstract. Conceptually close to this paper's own §5 lesson (don't run expensive machinery on every cycle if you don't have to) but applied to filtering rather than to fixing redundant table-rebuild overhead — a complementary optimization angle worth naming in §5/§8, not yet combined with this project's own fix.
37. [State Estimation of Power Systems Under Measurement Anomalies](https://www.mdpi.com/1996-1073/19/3/632) (MDPI *Energies*).
38. ★ [Linear State Estimation and Bad Data Detection for Power Systems with RTU and PMU Measurements](https://arxiv.org/pdf/2001.10764) (arXiv:2001.10764). Confirmed: linear WLS + largest-normalized-residual (LNR) test, mixed RTU/PMU measurement fusion, "several test cases of different sizes" (unspecified in the abstract) — no timing figures given, so not usable as a latency comparison point despite the topical overlap with this project's §5.

## G. Zero-day / unseen-attack generalization

39. ★ [An intrusion detection model to detect zero-day attacks in unseen data using machine learning](https://journals.plos.org/plosone/article?id=10.1371%2Fjournal.pone.0308469) (PLOS One). **Corrected after reading — the 58–68%/NSL-KDD/CIC-IDS2017 figures in an earlier pass of this list were wrong**, apparently invented or misattributed by the search summary that produced them; the actual paper uses CIC-MalMem-2022 only, with an 80/20 split (test rows just held out, not a held-out attack *family*, so not even the same experimental design as this project's §4), and reports ~99.98% accuracy — the opposite of a generalization-gap finding. This is not a citation for §4 as originally planned. Left in the list as a reminder to re-search for a genuine held-out-attack-family power-system or general-IDS reference, not removed silently.
40. [Explainable and Deployment-Aware Zero-Day Intrusion Detection for Cloud-Level Backend and Management Ecosystems in EV/V2X Cyber-Physical Systems](https://doi.org/10.3390/computers15090599) (MDPI *Computers*).
41. [A Unified Generative and Explainable Artificial Intelligence Framework for Trustworthy Intrusion Detection in Cyber-Physical Networks](https://www.sciencedirect.com/org/science/article/pii/S1546221826007666) (ScienceDirect).
42. ★ [A Novel Solution for Zero-Day Attack Detection in IDS using Self-Attention and Jensen-Shannon Divergence in WGAN-GP](https://arxiv.org/pdf/2603.19350) (arXiv:2603.19350, 2026). Confirmed, and genuinely useful: evaluated on NSL-KDD using a **"leave-one-attack-type-out" protocol** — methodologically identical to this project's own §6 (train with one attack family withheld, test recall on exactly that family). ## I. Microgrid / grid cybersecurity reviews (background/motivation citations)

46. [Cyber-attacks in Cyber-Physical Microgrid Systems: A Comprehensive Review](https://doi.org/10.3390/en16124573) (MDPI *Energies*, 2023).
47. [A review on machine learning techniques for secured cyber-physical systems in smart grid networks](https://www.sciencedirect.com/science/article/pii/S2352484723016323) (ScienceDirect).

49. ★★ [A Scoping Review of Machine Learning Applications in Power](https://arxiv.org/pdf/2509.09053) (arXiv:2509.09053, 2025) — **the single most useful supporting citation found in this pass**, worth its own paragraph in the paper draft's Discussion, not just a related-work mention. It reports, as a field-wide finding, exactly the two gaps this project's own results run into directly: (1) most ML-for-protection studies do not discuss computational latency/real-time constraints at all — directly motivates why §5's latency profiling is a real, not manufactured, contribution; (2) topology-aware generalization is under-tested field-wide — "most studies train on fixed test systems rather than investigating how models perform when grid structure changes," with reviewed work concentrated on IEEE 14/30/39-bus, single-topology evaluation, no cross-topology testing. This means this project's §7 (IEEE-14 scale pilot, however inconclusive/complicating) is not a niche self-inflicted problem — it is addressing a gap the field has already identified in itself but not yet filled.
50. ★ [Multidimensional Resilience for Electrical Power Systems: Systematic Review, Integrated Index, and Validation under Real-World Cyber-Physical Attack Scenarios](https://arxiv.org/pdf/2606.08062) (arXiv:2606.08062, 2026). Confirmed: a much broader-scope paper than first assumed — proposes a 5-dimension (physical/operational/digital-cyber/climatic-external/economic-regulatory) resilience index, validated against a scenario "inspired by the December 2025 attack on Polish energy infrastructure" (a real, recent, named incident worth a sentence in this paper's Introduction for motivation). Does **not** discuss latency or attack-type discrimination — treats "attack" as a unified stress scenario, not something to classify or localize. Background/motivation citation only, confirmed as such.

Attempted; abstract is high-level/conceptual only — no architecture, test system, or numbers extractable. Left unstarred despite a successful fetch, since there was nothing specific enough to cite.
55. ★ [Smart Grid Security: A Verified Deep Reinforcement Learning Framework to Counter Cyber-Physical Attacks](https://arxiv.org/pdf/2409.15757) (arXiv:2409.15757). Confirmed: a DRL agent that responds to attacks by triggering sequences of *existing* protection schemes (not learning new ones from scratch), formally verified via reachability analysis for safety rather than only empirically tested — a genuinely different assurance paradigm (formal safety proof vs. this paper's statistical/multi-seed validation) worth naming as a contrast in Discussion. No test system or numeric results in the abstract.
56. ★★ [Cyberattack Detection in Virtualized Microgrids Using LightGBM and Knowledge-Distilled Classifiers](https://arxiv.org/pdf/2601.03495) (arXiv:2601.03495, 2026). **The single most directly comparable latency number found in this whole pass.** Confirmed: MATLAB/Simulink virtual microgrid with heterogeneous renewables, attacks injected via MGLib at the control-pathway level; multiclass attack-type accuracy 99.72% (F1 99.62%), binary intrusion accuracy 94.8% (F1 94.3%); **inference latency 54-67 ms per 1000 samples, i.e. ~0.054-0.067 ms/sample** after knowledge distillation. This is the *classifier-inference* number, directly comparable to this paper's own §5 model-inference sub-step (LogisticRegression: 0.20ms/sample) rather than to our full pipeline total (16.4ms median) — both papers independently find classifier inference is cheap (sub-millisecond) once lightened, reinforcing §5's core claim that the *state-estimation* step, not the model, is where a real latency budget gets spent. Cite this precisely as a same-order-of-magnitude confirmation of the inference sub-step, not as a full-pipeline comparison — conflating the two would overstate the parallel.

## Honest caveat on this list, updated after a second pass

Only the ★-marked entries (30 of 56) were read past the search-snippet level. That second pass already caught two wrong claims from the first pass — §39's "58–68%" figures and §29's "94.11%" figure — both traced to specific-sounding numbers a search engine's AI summary attached to a paper that, read directly, didn't contain them. Both are now corrected in place rather than silently dropped. The practical rule this establishes for the rest of this list: **a specific number is not trustworthy until read from the source directly** — search-snippet summaries are reliable for topic/scope, not for citable figures. Anything below without a "corrected after reading" note has not yet been checked this way.

**Fetch reliability note**: in this second pass, arXiv `/abs/` pages succeeded 8/8 times; arXiv `/pdf/` links succeeded roughly half the time (some parse cleanly, some return only binary/compressed stream data); IEEE Xplore and ACM Digital Library links failed (403) every time attempted. Practical implication for finishing this list: retry unstarred arXiv entries via their `/abs/` URL before giving up on them, and expect to need a different tool (institutional access, Google Scholar cache, or the person's own library access) for the IEEE/ACM-hosted entries in clusters A, B, D, and E.
